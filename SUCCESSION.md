# Succession

**Status: NOT WRITTEN. This is a prompt sheet, not a draft.**

The brief is explicit that this gets written at G0, "while it costs nothing",
and that it is a human document. Nothing here should be taken as proposed
wording. What follows is only the set of questions the finished clause has to
answer, so that writing it is a matter of deciding rather than starting from a
blank page.

## Questions the clause must answer

1. **Who can remove the founder, and by what process?** A named person or body
   that is not the founder. If the answer is "nobody", the project has no
   succession clause, whatever this file says.

2. **What happens to the data if the project stops?** The records are only
   valuable if they outlive the organisation. Which licence, which archive,
   which custodian.

3. **Who holds publication authority if the founder is unavailable?** Rule 6
   requires a named human verifier. If only one person can verify, the project
   halts the moment they are unreachable — which is a design decision worth
   making deliberately rather than discovering.

4. **What triggers a wind-down rather than a handover?** The brief names
   conditions under which the project should narrow or stop. Who declares them.

5. **Who can amend this clause?** If the founder can amend it alone, it is not a
   constraint on the founder.

## Why this is dated at G0 rather than later

It costs nothing to write now and becomes contested exactly when it is needed.
The co-founder search opens at G0 and must close before G4; a person being asked
to join a project of this kind will reasonably want to read this file first.
